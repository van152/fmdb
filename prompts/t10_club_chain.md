# t10 任务书：club 链普查 —— 从"名字侧"反向攻 433 字段

## 一句话目标

阶段三的硬骨头是 club（433 字段，目前只闭合 1 个）与 nation（346 字段）。t04 已证负：club 的 reader 是 mixed 双 reader + 动态宽度，**行布局这条路走不通**。

本任务换一个方向：**如果 club 的 4CC 分发链是完整的，那么 `名字 → object_off` 可以完全不依赖 reader**。链里每个码的 getter 都读某个 `[reg+OFF]`，把这些 OFF 收集起来，若它们构成一个**单调、不重叠、覆盖连续的 struct 偏移集合**，那 club 的字段偏移结构就被反推出了——这是与"reader 宽度累加"完全独立的第二条路。

你要回答的是**可行性**，不是"解完 433 字段"。判定要硬：给出数字，允许负结果。

## 四步，全部要数字

### 步骤 1：码表盘点

从 `schema_inventory.json` 取出 club 表的**全部字段名**（应为 433 个，若你的计数不是 433 请报告实际数与差异原因）。然后：

- 有多少字段名**恰好是合法 4CC**（4 个 ASCII 可见字符、区分大小写）？
- 其中在 `4cc_table.json` 里有候选的有多少个？（给出 `命中/总数` 与百分比）
- 这些命中的码，`object_off` 的**集合**：多少个不同偏移、最小/最大、是否有重复、是否有落在 `0x20..0x400` 之外的。

**注意命名差异**：FM 的 4CC 常是"字段名截断/变体"（如 `Cccn` vs schema 里的长名）。所以除了精确匹配，还要报告**前缀/编辑距离 ≤1 的模糊匹配**数量，并明确标注哪些是"精确"哪些是"推断"。

### 步骤 2：链分组

用与 t08 相同思路（按 `file_off` 排序 + 相邻间距聚合 + `je` 目标可达性校验），把 club 相关的 cmp 点聚成链：

- 报出所有 `n_codes >= 20` 的链，含 `file_off_range / n_codes / 码表样例`;
- 判断哪条链是 club 链：判据是**该链的码集合与步骤 1 的 club 码命中集合重合度最高**（给重合数/重合率）；
- 若存在多条候选链，全部列出并给裁决理由，不许只报一条。

### 步骤 3：偏移结构一致性（本任务的核心判据）

假设链 C 是 club 链。取其 `(code, object_off, size)` 三元组集合 S，检验：

| 检验项 | 通过条件 |
|---|---|
| 单调性 | 按 `object_off` 排序后，`size` 与偏移差不矛盾（即无重叠：`off[i] + size[i] <= off[i+1]`） |
| 覆盖率 | `[min_off, max_off]` 区间内被字段覆盖的字节比例（报百分比） |
| 对齐性 | 偏移是否满足自然对齐（w4 → off%4==0，w2 → off%2==0）的百分比 |
| 空洞 | 未覆盖区间列表，以及这些空洞里是否有 `bitfield`（共享偏移的多码）可解释 |

**判定规则（硬性）**：
- 若"无重叠率 ≥ 95%"且"对齐率 ≥ 90%"，则**反向布局可行**，进入步骤 4；
- 否则**判定不可行**，如实报负结果，并指出是哪个检验项崩了（这同样是有价值的结论，能反过来解释 t04 为什么难）。

### 步骤 4：仅当步骤 3 判定可行时

产出 club 的 `名字 → object_off` 候选表（`candidates_club.json`），每个条目带 `confidence ∈ {exact, fuzzy, ambiguous}` 与 `why`。**明确声明：这是 object 层偏移，不等于行内偏移**；若要转成 row_off 需要 reader 侧证据，不在本任务范围。

同时给一句话判断：**433 个字段里，用链能定到偏移的有多少个、还剩多少个必须走 reader**。
