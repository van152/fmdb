# t13d 旁路任务：四张表的候选实体快速数据侧诊断

## 性质说明

这是**旁路交叉检查**，不是主线。你的输出只作参考，主线的裁决由指挥官独立进行；**你没有产出也不会阻塞任何事**。所以请尽快给结论，不要追求完备。

## 任务

只读诊断下面 4 张 server 表，看它们的现有"候选实体"是否与数据相符：

| table_type | count | t11 给的候选实体 |
|---:|---:|---|
| 22 | 449 | club |
| 30 | 72,473 | player |
| 34 | 7,115 | club（此前的版本曾判 nation，两种说法都要考虑）|
| 49 | 792,149 | person |

## 做法

1. 用 `scripts/fm24_dump.py --archive server --table N --csv <输出路径> --limit 999999` 导出（只读调用，输出到 `scratch/t13d/out/`）。
2. 对每张表看前 20 列的：distinct、min/max、0 与 0xFFFFFFFF 的比例、是否有类似身份 ID 的稳定列。
3. 拿这些数字与候选实体的已知基数比较：club 主表行数约几千、player 约 7 万、nation 251、person 约 79 万。判断"量级吻合 / 不吻合 / 无法判断"。
4. 特别注意 **t34**：如果它的列看起来像"国家 ID 引用"（值域 ⊆ [0,251)）就支持 nation；如果看起来像俱乐部属性就支持 club。

## 交付（只写 `scratch/t13d/out/`）

1. `quick_audit.md` —— 4 张表逐张给：量级判断 + 3 个最有信息量的列统计 + 一句结论。
2. `audit.json` —— 同内容的机读版，顶层 `"status"`。

## 硬约束

- 只写 `scratch/t13d/out/`，其他目录一律只读。
- `py -V:3.12 -I`；不许联网、不许启动游戏/编辑器。
- **你是旁路，若中途卡住就直接把已得到的部分写盘并标注 `"status":"partial"`，不要反复重试耗时间。**
- 不许把"量级吻合"写成"已确认实体"——那是锚点裁决的事，不归你。
