### 3.3 weather(27)— 每块 4 组,双档同构

行文法:4×(u32 len + UTF-8 名) + **95B 数值中段** + 13B 身份。

**95B 的拆分是本表的关键判据**:

```
95 == 3 (零前缀) + 4 × 23
```

钉死方式:遍历中段全部 95 个字节,**值集恰为 `{0,100}` 的列只有 25/48/71/94**,
而 `3 + 23b + 22` 对 b=0..3 正好给出 25/48/71/94,且这 4 列**逐行相同**。
竞争假设 `3 + 4×22 + 4` 会让这 4 列变成 25/47/69/91 而失去一致性,
且三组「和==100」命中数从 **1519 掉到 583**(满分 12×334 = 4008)→ 否证。

每块 23B 的映射(4 块同构):

| 相对偏移 | 字段组 | 级别 | 证据 |
|---|---|---|---|
| `+0` | `w{b}sd` 起始日 | **L2** | u8 0..253,≤365;块内头部唯一非常量字节 |
| `+1` | `w{b}dn` 昼夜差 | candidate | 23B 装 22 字段 → 唯一剩余字节;但值集只有 `{0,1}`,**不符合 0..50**,按排除法指派 |
| `+2..+6` | `w{b}p0..p4` 降水 | **L2** | 5×u8 各 ≤100,和==100 命中 316/318/312/314(满分 334;失败全是整块全零行) |
| `+7..+11` | `w{b}w0..w4` 风 | **L2** | 同上,317/319/318/315 |
| `+12..+21` | `w{b}te,tv,t0..t7` 温度 | **L2** | 10×u8 各 ≤100,与 schema 每块 10 个温度字段数吻合;和==100 命中 244/91/248/285,**>105 的行数为 0** → 组有界,但"和==100"只是近似不变量 |
| `+22` | — | unassigned | 全中段唯一 `{0,100}` 列,4 块**逐行相同** → 行级属性而非块内字段 |

**组内顺序(p0..p4 / w0..w4 / te..t7)一律不猜**:数据侧无区分信息,只给"字符串区+
长度规则"级别的证据(组边界、字节宽度、值域、闭合和),不强配 4CC 顺序。

`+22` 的 20 个命中行名字全是干旱/热带区(Rub Al-Khali Desert、Gobi Desert Region、
Saudi *、Türkiye *、South China Sea Coast),且与"温度全零行"**零重叠**(20 vs 14,交集 0)。
它像一个行级气候标记,但 weather.xml 里没有对应字段 → **留空不硬套**。

### 3.4 local_region(47)— 变长 lcrg_tail,双档 109,505B / 2,488 行

**文法修正(相对上游)**:上游 44B 定长已被 t74 否证;本仓为变长。本任务进一步定死:

```
row_len = 23 (固定前缀) + 5×(k+1) (条目) + 13 (身份) = 41 + 5k
```

关键点:条目数是 **k+1 而非 k**,数组起点是 **23 而非 28**。早先把数组放在 28 并
读 k 个条目也能"闭合",但那是因为**首个条目的 pct 恒为 0**(2,488/2,488),
被误当成了填充零。按 23+5(k+1) 读,`biz_len == 23+5(k+1)` 对 2,488/2,488 行成立。

| `duni` | −9 | **L3** | 同上 `duni=-9`;u32==u32≠0 + 0 标记 |
| `Lpop` | 4 | **L2** | u32 0..81,330,531,全部 ≤1e9(644 个 0);schema 唯一无上界整数 |
| `Lrll[i].Llgp` | 23+5i | **L2** | u8 全部 ≤100;行内 pct 和==100 命中 **869/1108** 行(k>0)——百分比列表的组闭合不变量 |

## 4. 校准:引用槽存的是**稠密序数**,不是 UID

这是本轮跨任务的关键口径,已用**与本任务无关的两张表**独立重推(`verify.py` 内复算):

| 锚点 | 结论 | 数值 |
|---|---|---|
| stadium `Scti@3` → city | **100% < 56,293**,顶值 56,290 | max/N = 1.000 |
| city `Cwea@14` → weather | **100% < 334**,顶值 333 | max/N = 1.000 |

若按 UID 解释,stadium `Scti` 对 city UID 集只命中 11%。**故引用槽 = 目标表的行序数。**

**这条校准同时给出一个反陷阱**:`Dfma@20`(出席人数,0..82,100)在数值上"完美落在
club(84,259) 序数域内"——但这个拟合**是空洞的**,因为 200,000 上限的标量本来就不会
超过 84,259。`slots_client_18.json` 里该槽显式带 `"vacuous": true` 标注,
**不因数值巧合升格为引用**。
