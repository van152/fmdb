# t15c · 658,011 vs 792,149 悬案(people_diff.md)

**一句话**:134,138 不是"多出来的实体数",而是两个**互不相关量**的净差:

```
t49 行数           792,149
  ├─ 命中 person    626,688  (79.12% 行, 213,513 distinct)
  └─ 未命中         165,461  (20.88% 行,  65,596 distinct)
person 基数        658,011   ← basic_people_db 自己的行数

165,461 − 31,323 = 134,138 = 792,149 − 658,011
```

`31,323` 是"命中行数 − person 基数"的残差。它没有实体含义,只说明:**把两个数相减得不出实体数**。

> **E59 不循环性检查**:658,011 来自 `basic_people_db` 的独立行数(4 路计数一致,见
> `scratch/t13e/out/baselines.json`),**不是**从 t49 数出来的;792,149 是 t49 自己的行数。
> 两者是独立测量,相减/相除合法。但下文凡是用 t49 行数当分母的地方都显式标注了 `[t49自身]`。

---

## 一、可检验结论(只用已有数字)

### C1. t49 的 `@4` 与 basic_people_db 的身份空间是**同一编码族**

- `@4` min 3 / max 2,000,342,690 / distinct 279,109。
- 与 person `duni` 精确相交:**213,513 / 279,109 distinct = 76.5%**;**626,688 / 792,149 行 = 79.12%**。
- 随机基线:若值均匀落 32-bit 空间,命中率约 `646,979 / 2^32 ≈ 0.015%`。实测高 4 个数量级。
- **高位字节(tag)分布两边共享**:duni 侧 tag ∈ {0,1,2,3,4,5,7,17,42,83,88,114,119},
  t49 缺失侧 tag ∈ {0,1,2,3,4,5,66,83,119}。tag 0..5 与 119 两边都有,
  tag 119 是 2e9 基址块(duni 侧 249,601 个值落在 `[2,000,005,711 .. 2,002,040,995]`)。
  → 不是"两个不同空间碰巧有交集",是**同一个 ID 生成器**,只是 t49 见到了一些 person 表里没有的号段。

### C2. basic_people_db 的 658,011 本身是**两个身份批**的和

| 批 | 数量 | 依据 |
|---|---|---|
| 有 duni 值 | 646,979 | `person_duni.npy` distinct = 646,979 |
| 无 duni 值 | 11,032 | `person_uid_all`(658,011 个序数 0..658,010 全在) − `person_uid`(646,979 个,max 656,817) |
| 合计 | **658,011** | 与基线一致 |

- 无 duni 那批的序数**聚在 972..656,817 + 658,003..658,010 两端**,不是随机缺:
  低段缺 9,839 个、尾段缺 1,193 个。
- `person_ids.npy` distinct = 657,788(比 658,011 少 223)→ 有 223 个序数连 id 都没有。

### C3. t49 引用了**几乎全部** duni 批的一部分,但漏掉大多数 person

- 有 duni 的 646,979 人里,t49 只引用了 **213,513(33.0%)**;**433,466 人从未被引用**。
- 说明 t49 不是"每人一条历史",而是**按事件出现的历史记录**(rows/distinct = 2.84)。
- `[t49自身]` 792,149 / 279,109 = 2.8381 行/引用 ID。

### C4. 缺失的 65,596 个 distinct ID **既不在 basic_people_db,也基本不在两个 hist 表里**

| 检查 | 命中 | 占 65,596 |
|---|---|---|
| 在 `pl_hist_id.dat` | 219 | 0.33% |
| 在 `non_pl_hist_id.dat` | 1,043 | 1.59% |
| 在两者之一 | 1,247 | 1.90% |
| **两者都不是** | **64,349** | **98.1%** |

- 反向检查:11,032 个无 duni 的 person 中,t49 只引用了 **75 个**。
  → 不能用"t49 引用了无 duni 的那批人"来解释 65,596 的缺失(只解释 75 个)。

### C5. 缺失 ID 的数值分布:98% 落在 ≥16.7M,最大 2,000,342,690

| 值域 | 缺失 distinct 数 |
|---|---|
| < 65,536 | 889 |
| 65,536 – 658,011 | 4,963 |
| 658,011 – 1,048,576 | 4,232 |
| 1,048,576 – 16,777,216 | 14,977 |
| 16,777,216 – 268,435,456 | **36,540** |
| 268,435,456 – 2,147,483,648 | 3,995 |
| ≥ 2,147,483,648 | 0 |

- **只有 5,852 个缺失值 < 658,011** —— 如果 t49 是"person 序数 + 少量溢出",缺口应该在低端;
  实际 98.1% 的缺口在高位段。这与"t49 用了比 basic_people_db 更大的身份池"一致。
- 缺失值**不是连续块**:相邻差为 1 的比例仅 12.0%,即稀疏编号。

### C6. 第 2 层修正:`@4` distinct(279,109) 远小于 person 基数(658,011)

- 279,109 / 658,011 = **42.4%**。所以"134,138 个多出的实体"这种读法从一开始就不成立——
  t49 引用的**不同人比 person 表总数少 378,902 个**。行数多 ≠ 人多。

## 二、假设(可判伪,按优先级)

### H1(最简)· t49 的历史池包含非球员/退役/员工实体,这部分不在 basic_people_db
- 支持:64,349/65,596 缺失 ID 不在任何已解析 id 表;`non_pl_hist_dt.dat`(27.6 MB)**未解析**。
- 判伪方式:解析 `non_pl_hist_dt.dat` 的 person 引用列,看 64,349 里有多少命中。
  若命中 > 50%,H1 基本成立;若 < 5%,H1 倒。

### H2 · 2e9 带是"另一套编号方案",不是 person
- 支持:duni 侧 tag 119 有 249,601 个值全部落在 2.0e9 带且**只填了 2.03M 跨度的 12%**;
  t49 缺失侧同带只有 3,991 个且稀疏。
- 判伪方式:检查 tag 119 值是否与 `person_uid` 的 0..656,817 存在**一一映射**
  (2e9 + k ↔ uid)。若映射到全部 249,601 个 uid,则 2e9 只是"带前缀的同一实体",H2 倒、H1 加强。

### H3 · t49 存的是"某一时点的历史快照",含已被删除/合并的 person
- 支持:缺失 ID 稀疏(非连续)、高位段为主、5.8% 低端;行/人 = 2.84。
- 判伪方式:在**任一新存档**里重跑 t49 的 `@4` distinct,看 65,596 中多少消失(需用户授权,当前不做)。

### H4(需警惕)· `@4` 不是纯粹的 person 引用,可能带 tag/类型位
- 支持:tag 分布 9~13 个离散值,不是均匀;`@4` 与 `@0/@1` 的语义都未定位。
- 判伪方式:找 t49 的 `@4` 与 `@21`/`@25`(d=245,324 / 523,437)的配对关系;
  若 `@4 >> 24` 与另一列的取值一一对应,说明高位是类型 tag,`@4` 需先 mask。
  **注意**:用 `miss >> 24` 去查 duni 命中得 15,688/65,596(23.9%),而原始值命中 0
  —— 这条已经显示"高位掩码后能救回 1/4 的缺失",方向与 H4 一致,但不足以定案。

## 三、明确不能说的话

- ❌ "t49 有 792,149 个人"—— distinct 只有 279,109。
- ❌ "多出 134,138 个实体"—— 恒等式巧合:165,461 − 31,323 = 134,138,31,323 无实体含义。
- ❌ "658,011 是从 t49 数出来的"—— 它来自 basic_people_db 独立计数(E59 已纠正)。
- ❌ "缺失的 65,596 全是非球员"—— 只有 1.9% 在已解析的 hist id 表里,其余是**未知**,
  不能把"未知"写成"非球员";当前证据等级:**C 类**(分布形状吻合,无独立事实)。
