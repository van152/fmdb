**方法说明**:文法 A 走不通后,我改为"找 trailer 而不是找 header"。

## 三、行数 / key / duni 统计

### 3.1 文法 A(compact,class-5 专属)

| 项 | 值 |
|---|---|
| 行数 | **1,193** |
| key 范围 | `[656,818, 658,010]`,**连续无缺**,唯一 |

| 空名 | 1 行 |
| `unk` 字节 | 恒 0 |

### 3.2 与 basic_people_db 的关系(**互补,不是重叠**)

`basic_people_db` 解压 54,060,043 B,头部 count = 658,011,按 class 行宽
(`{1:83, 2:83, 3:83, 4:34, 5:22}`)走完全部 658,011 行,`walk_end = 54,060,034`,
`walk_bad = null` → **闭包成立**。class 分布
`{1:166,064, 2:476,158, 3:4,757, 4:9,839, 5:1,193}`。

| 判据 | 结果 |
|---|---|
| compact 行数(1,193) = class-5 行数(1,193) | ✅ **完全相等** |
| compact key 区间 `[656,818, 658,010]` = basic_people **尾块** ordinal 区间 | ✅ 相等 |
| basic_people 尾块是 class=5、`duni_first=2,002,040,996` | ✅ 与 compact 首 duni 相等 |
| 同 ordinal 逐条比 duni(1,193 条) | ✅ **1,193/1,193 全等** |

→ 文法 A 段 **就是** `basic_people_db` 里 class-5 那 1,193 行的同一批记录。
两份档案是**互补视图**,不是超集/子集关系。

### 3.3 覆盖率(尾部签名法)

| 口径 | 值 |
|---|---|
| 命中 key 总数 | **658,011 / 658,011 = 100.000%** |
| 按 class | 1: 166,064/166,064;2: 476,158/476,158;3: 4,757/4,757;4: 9,839/9,839;5: 1,193/1,193 |
| 每 key 的 trailer 一律 `duni == basic_people[key].duni` | 是(去重后 658,011 个独立 position) |
| position 分布 | 每 16MB 约 2.7 万行,全文件均匀(24/25 个 16MB 窗口非空) |
| trailer 间距 | 中位 644 B,p10 365 B,p90 772 B(含 body) |

**按位置排序后 key 不单调**(corr(key, q) = −0.064,递增比例 50.1%),
所以 people_db 的行序**不是** ordinal 序 —— 这一点与 basic_people_db(ordinal==行号,已实测)不同。
头部那 1,193 条 class-5 是全文件唯一按 key 顺序排的一段。

## 四、假设裁决

**命题**:"people_db.dat 承载 658,011 条完整 person 记录"

**裁决:`supported`(有保留)。**

**支持(定量)**
1. 尾部签名在 658,011 个 key 上全部命中,且 `(key2, duni)` 与 `basic_people_db`
   同 ordinal 的 duni **逐条相等** —— 这是两个独立文件、两条独立解析路径的对齐
   (L1 + L2)。
2. 按 class 覆盖 100%,无类别系统性缺口。
3. 头部 `u32@2 = 658,011` 与 class 分布之和 `166,064+476,158+4,757+9,839+1,193 = 658,011` 自洽。
4. 每 key 只有一个规范 trailer position(去重后 658,011 个),没有 key 复用/歧义。

**保留(不能说满的地方)**
1. **行内 body 语法未解**:目前只锚定到 trailer,`name→trailer` 之间的 body
   (长度约 400–770 B)字段含义全部未定。所以"658,011 条记录存在"成立,
   "每条记录的字段布局"**不成立**。
2. 覆盖率依赖 `basic_people_db` 做校验,若两份档案同源同错,则这是**循环验证**风险;
   当前唯一独立锚点是 `t15c` 的 `person_duni.npy`(distinct 646,979)—— 646,979 个非零
   duni 全部出现在 payload 中(100%),但该检查只能证"值出现过"。
3. 文法 B 的 186,108 是**下界**:只认首字符大写且有拉丁字母的 UTF-8,
   非拉丁名/匿名行(comp 行等)会漏计,不能当作 person 行数。

**反对(已排除的替代假设)**
- ❌"people_db 只有 1,193 条记录"—— 尾部签名在 658,011 个 key 上全部命中。
- ❌"people_db 是 basic_people 的超集,含 basic_people 没有的人"——
  key 空间完全落在 `[0, 658,010]`,与 basic_people ordinal 一一对应,无额外 key。
